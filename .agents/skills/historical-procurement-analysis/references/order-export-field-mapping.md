# 订单导出字段映射（真实样本验证）

本文件用于将企业订单导出历史采购明细映射为 `historical-procurement-analysis` 的标准字段。

> 仅保存字段规则，不保存真实联系人、电话、地址、供应商名称等业务敏感数据。

## 1. 核心字段映射

| 原始字段/常见同义字段 | 标准字段 | 主要用途 | 级别 |
|---|---|---|---|
| 协议编号 / 协议号 / 合同编号 / 合同号 / 框架协议编号 / 采购协议编号 | `agreement_number` | 用户选择历史分析范围 | **必要** |
| 订单编号 | `order_id` | 订单去重、采购频次 | 必要 |
| 订单状态 | `order_status` | 仅保留已完成/执行中 | **必要** |
| 订单创建日期 | `order_date` | 周期识别、同比/趋势 | 必要 |
| 物料编码 | `material_code` | SKU 稳定标识 | 必要 |
| 物料名称 | `material_name` | SKU 识别 | 必要 |
| 物料规格 | `specification` | SKU 可比性 | 必要 |
| 品牌 | `brand` | SKU 可比性 | 可选 |
| 数量 | `quantity` | 历史采购量基线 | 必要 |
| 单位 | `unit` | 单位一致性 | 必要 |
| 含税单价 | `tax_included_unit_price` | 历史价格基线 | 必要 |
| 不含税单价 | `pre_tax_unit_price` | 未税价格分析 | 可选 |
| 税率 | `tax_rate` | 税口径一致性 | 必要 |
| 含税总额 | `tax_included_amount` | 支出分析 | 必要 |
| 不含税总额 | `pre_tax_amount` | 支出分析 | 可选 |
| 供应商名称 | `supplier_name` | 历史合作/集中度 | 必要 |
| 供应商编码 | `supplier_code` | 供应商稳定标识 | 可选 |
| 收货地址 | `delivery_location` | 项目/区域汇总 | 必要 |
| 地址省份 | `province` | 区域分析 | 可选 |
| 地址城市 | `city` | 区域分析 | 可选 |
| 商品一级分类名称 | `category_level_1` | 品类分析 | 可选 |
| 商品二级分类名称 | `category_level_2` | 品类分析 | 可选 |

## 2. 分析前置顺序

字段识别后必须按以下顺序处理：

```text
协议编号识别
↓
列出全部协议概览
↓
用户明确选择一个或多个协议
↓
只保留所选协议
↓
订单状态过滤（已完成/执行中）
↓
周期完整性判断
↓
SKU + 区域分析
```

不得先做总量统计再选择协议，否则会把未选择协议数据混入结果。

## 3. 协议字段缺失

若无法识别 `agreement_number`：

- 标记 `missing_agreement_field`；
- 不默认用整个文件作为一个协议；
- 要求用户提供协议字段映射或明确的协议范围。

无协议编号的明细默认排除，只有用户明确确认后可作为例外纳入。

## 4. 周期识别

在同比或年度预测前读取有效订单的最早/最晚日期。

- 完整年度或明确可比周期：可用于预测；
- 部分周/月：可做采购量、金额、价格、SKU占比和区域分析，但不得机械年化。

## 5. SKU 聚合键

优先：

`agreement_number + material_code + specification + unit + region`

无物料编码时退化为：

`agreement_number + material_name + brand + specification + unit + region`

不同协议中的同名 SKU 不得在未校验规格/单位的情况下直接合并。

## 6. 金额与价格规则

优先使用行级 `含税总额 / 不含税总额`，并校验：

`数量 × 单价 ≈ 行级金额`

同一 SKU 价格变化时输出最低价、最高价、加权平均价和最近成交价，避免简单平均掩盖数量差异。

## 7. 数据隐私

真实订单中的联系人、电话、详细地址、公司主体及供应商名称只用于当前任务分析，不应作为公开示例上传代码仓库。
