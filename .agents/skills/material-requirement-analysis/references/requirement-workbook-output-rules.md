# 需求清单 Excel 强制输出规则

## 1. 触发条件

当 `material-requirement-analysis` 完成人工澄清后，如果：

`P0 blocker count = 0`

则必须生成需求清单 Excel。

P1/P2 尚未解决不构成不生成 Excel 的理由。

## 2. 输出状态

### clarified_with_pending_nonblocking_items

- P0 = 0
- 仍有 P1/P2
- 输出：`{{项目名称}}-澄清版需求清单.xlsx`

### confirmed

- P0 = 0
- 关键需求和商务条件已确认
- 输出：`{{项目名称}}-最终需求清单.xlsx`

## 3. 模板优先级

1. 当前用户提供的原始 Excel 需求清单：优先复制并保留版式；
2. 当前项目已有企业需求模板；
3. Skill 内置 `templates/标准需求清单模板.xlsx`。

不得直接覆盖用户原始文件。

## 4. 必须写入的采购需求字段

- 序号
- 区域（多区域时必须显式）
- 名称
- 品牌（有采购要求时）
- 规格/型号/容量/包装
- 单位
- 起订量（如有）
- 年度预计采购量
- 备注

以及能映射到模板的项目级信息：采购周期、配送范围、报价口径、付款/账期、合作期限、数量约束等。

## 5. 供方报价字段

以下字段如果原模板存在，应保留但为空：

- 含税单价
- 未税单价
- 税率
- 含税总价

不得写入历史价、旧报价、市场价或 AI 测算价。

## 6. P1/P2 留痕

非阻断事项可以：

- 写入对应行“备注”；
- 或写入单独“待确认事项”区域/工作表。

但不得篡改已确认的需求事实。

## 7. 一致性检查

输出前检查：

- Excel SKU 数 = Structured Requirement SKU 数；
- 区域一致；
- 品牌/规格一致；
- 年度预计采购量一致；
- 项目级商务条件一致；
- 供方报价字段未被预填。

## 8. 完成判定

P0 清零后，如果只输出文字/YAML/JSON而没有 Excel：

`skill_execution_status = incomplete`

只有 Excel 成功生成并与 Handoff 一致后，才允许：

`skill_execution_status = complete`
