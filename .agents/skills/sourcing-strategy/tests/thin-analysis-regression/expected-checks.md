# Expected checks

## A. 支出分析

必须通过：

- 明确写出历史数据覆盖期；
- 同时出现 600,000 元历史实际支出与 1,200,000 元12个月年化基线，并区分实际值/年化值；
- 至少列出3个区域/项目维度金额与占比；
- 至少列出5个SKU维度金额与占比；
- 至少列出3个历史供方支出及占比；
- 应识别 SKU-A 为最高支出SKU，历史供方A为最高支出供方；
- 至少3条带数字证据的关键发现；
- 至少2条直接对应本项目的采购策略含义；
- 不得把6个月60万元直接表述为全年支出；
- 不得只输出“整体 / 军种维度 / SKU维度”等标题。

## B. 当地供应市场行情分析

必须通过：

- 内部供应信号至少体现：12家官方匹配、8家明确覆盖、6家邀约、5家回复、4家短名单；
- 应分析120天账期接受风险；
- 应分析零散配送最低起送额对报价/履约的影响；
- Web可用时至少3个独立公开来源；
- 外部分析至少覆盖供应格局、上游/成本、物流履约、价格趋势、政策/标准中的可获得内容；
- 至少3条与项目直接相关的采购含义；
- 无可信成本比例时不得虚构材料/人工/利润占比；
- 公开市场企业不得被加入邀标候选池或短名单。

## C. 模板与完整度

必须通过：

- `spend_analysis.completeness_status` 存在且取值合法；
- `market_analysis.completeness_status` 存在且取值合法；
- DOCX 不残留 `X` / `XX` / `XXX` / `X%`；
- 不存在空的“市场情况 / 成本构成情况”等标题；
- 供应商名称不得拼接到“当地供应市场行情分析”等章节标题；
- `consistency_checks.spend_analysis_complete_enough = true` 才允许进入可报批状态；
- `consistency_checks.market_analysis_complete_enough = true` 才允许进入可报批状态。

任一关键项失败，则本测试应判 FAIL，不得把内容过薄的报告视为成功。
