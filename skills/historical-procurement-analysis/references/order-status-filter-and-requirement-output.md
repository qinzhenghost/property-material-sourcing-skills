# 订单状态过滤与需求清单输出规则

## 一、订单状态过滤（强制）

历史采购分析的第一步不是统计，而是过滤订单状态。

### 保留

仅保留：

- `已完成`
- `执行中`

### 剔除

所有其他状态均不进入历史采购基线，包括但不限于：

- `已取消`
- `已退货`
- `取消`
- `退货`
- `已作废`
- `关闭`

不得根据订单名称、付款状态、发货状态或收货状态猜测订单是否有效。

### 审计输出

至少记录：

```yaml
order_status_filter:
  filter_status: applied
  status_field: 订单状态
  allowed_statuses:
    - 已完成
    - 执行中
  total_rows: 100
  included_rows: 82
  excluded_rows: 18
  excluded_by_status:
    - status: 已取消
      count: 10
    - status: 已退货
      count: 8
```

### 缺少状态字段

如果历史数据不存在订单状态：

- 不得默认全部有效；
- 标记 `missing_status_field`；
- 只有采购员明确确认“此数据已经预过滤，仅包含有效订单”后，才能使用 `user_confirmed_prefiltered` 继续。

## 二、需求清单输出

固定模板：

`templates/需求清单模板.xlsx`

固定输出：

`{{项目名称}}-历史测算需求清单.xlsx`

### 可回填字段

- 序号
- 区域
- 名称
- 品牌
- 规格
- 单位
- 起订量（仅有明确依据时）
- 年度预计采购量（仅预测条件满足时）
- 备注

### 禁止回填的供方报价字段

- 含税单价
- 未税单价
- 税率
- 含税总价

历史参考单价与内部预计采购金额必须保留在分析结果/Handoff中，不能放进供方报价列。

### 区域要求

当历史订单包含多个区域时，一行需求必须对应明确的：

`SKU + 区域`

如果无法确认区域映射：

- 不分配数量；
- 标记待人工确认；
- 不根据行号猜区域。

### 无法年度预测时

仍可生成需求清单草稿：

- 填入SKU、区域、规格、单位等已知事实；
- `年度预计采购量` 保持空白；
- 备注写明原因，例如“历史样本仅覆盖部分周期，年度数量待确认”。
