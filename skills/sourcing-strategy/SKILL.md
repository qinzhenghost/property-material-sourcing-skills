# Sourcing Strategy

## 1. Purpose

固定输出：

1. `{{项目名称}}-strategy-data.yaml`
2. `{{项目名称}}-采购方案报告.docx`

DOCX 必须以 `templates/物资采购方案报告模板.docx` 为底稿，不从空白文档重建。

核心原则：

> 不是“把模板填满”，而是按照模板栏目把已验证事实组织成可报批的采购逻辑：数据/事实 → 分析判断 → 采购动作。

必须同时读取：

- `references/procurement-plan-template-mapping.md`
- `references/report-content-quality-guide.md`
- `references/template-v3-content-blueprint.md`
- `references/market-intelligence-policy.md`

历史优秀案例只能学习结构和分析方法，不得复制其中项目名、供应商、金额、人员、日期、成本比例、降本率、保证金或定标规则。

## 2. Entry Gate

标记 `ready_for_approval` 前至少满足：

1. confirmed requirement 已形成；
2. 项目名称、采购周期/需求时间、采购方式、配送范围明确；
3. 预算金额或预算形成逻辑明确；
4. `supplier-shortlist.strategy_handoff.human_confirmation.shortlist_confirmed = true`；
5. 当前项目供应商选择方法/定标规则、关键商务条款已确认；
6. 支出分析通过 V3 Spend Gate；
7. 当地供应市场行情通过 V3 Market Gate；
8. DOCX 无 `X / XX / XXX / X%`、空分析标题、历史案例残留、字段错位或供应商名称串入章节标题；
9. 模板空间不足时已扩展内容区域，而不是压缩或删减分析。

任一关键项不足，可生成 `draft`，不得冒充 `ready_for_approval`。

## 3. Inputs

### Required

- `material-requirement-analysis` confirmed requirement；
- `supplier-shortlist.strategy_handoff` 的人工确认最终短名单；
- 企业 V3 采购方案模板；
- 当前项目采购方式和关键规则。

### Strongly preferred

- `historical-procurement-analysis.strategy_report_handoff`；
- 历史订单结构化记录；
- `sourcing-invitation` 的官方供方匹配、区域 coverage gap、邀约/回复、bid_bond；
- 项目预算、参考价、历史价格；
- 供方对账期、配送、起订量/最低配送金额、保证金等反馈；
- 当前地区 + 当前品类的公开市场价格、成本、供需、标准和监管资料；
- 招标计划、评标成员、风险补充。

如果历史 Handoff 只给粗粒度结论，但运行上下文仍能访问同一协议范围的已验证有效订单，可以补充计算模板所需维度；必须沿用相同协议范围、订单状态过滤和税口径，并记录计算依据。

## 4. Source Hierarchy

### Tier A — Internal confirmed facts

已确认需求清单、所选协议有效历史订单、官方供方库、人工确认最终短名单、企业当前规则、采购员确认信息。

### Tier B — Calculated facts

历史金额/数量/订单数、区域/业务单元/SKU/历史供方占比、订单金额段、Top SKU/Pareto、平均订单金额、历史均价/价格波动、年化基线、预测金额、供方数量、前序已计算投标保证金。

所有计算必须可追溯。部分周期实际值与12个月年化/预测值分开；含税/未税不得混用。

### Tier C — Public market intelligence

只用于当地供应格局、原材料/制造/包装/仓储/人工/物流成本驱动、公开价格趋势、行业供需、标准监管和市场风险。

公网资料不得新增当前邀标候选供方。

Web 可用且地区、品类明确时，必须主动研究公开市场，原则上至少 3 个相互独立来源并优先近 12 个月资料。重要结论保留 `source / source_date / evidence_summary / confidence`。

### Tier D — Human Decision

AI 不得擅自决定最终预算、中标/备选家数、定标方法、份额划分、目标降本率、评标成员、废标/转竞谈审批规则、保证金规则变更、正式最低起送金额/免运额度。

## 5. V3 Template-first Generation Contract

### 5.1 项目头部

填写项目名称、采购方式、需求时间、预算金额；预算必须说明含税/未税及来源。

### 5.2 需求背景简介

至少覆盖：基本情况、使用场景、配送范围、交付要求、原协议/续采背景、历史采购趋势、清单形成逻辑和本次采购目的。

结尾必须回答：为什么现在采购、此次采购主要解决什么问题。

### 5.3 标段或标的划分

至少说明 SKU 数量、预计总量、品类/品牌/规格结构、区域特殊项、标段数量和划分逻辑。未确认不得自行拆标。

## 6. 支出分析 — 严格对应最新模板四个子块

最新模板支出分析必须按以下四块处理，不得把内容压缩成一句话或只保留标题。

### 6.1 `1、整体`

有历史数据时至少包含：

- 数据覆盖期；
- 所选协议范围、有效订单状态口径；
- 有效订单数/明细数（可得时）；
- 历史实际采购金额及税口径；
- 平均订单金额（可得时）；
- 部分周期时同时展示实际金额与12个月年化/预测金额；
- 当前预算/预测与历史基线的关系；
- 1 段整体判断。

如区域/配送地址维度可用，应在“整体”中增加区域结构分析：主要区域订单数、金额、占比，以及跨区县/跨城市/跨省配送对成本和时效的影响。

### 6.2 `2、军种维度`

“军种”只是模板展示名称，必须映射为源数据真实存在的军种、业务单元、业态、项目、客户线或组织字段。

有数据时：

- 使用模板表格填 `业务维度名称 / 采购金额 / 占比`；
- 可得时补订单数；
- 至少列 Top 3，不足 3 个则全部；
- 分析需求是否高度集中于单一业务单元，以及是否影响配送、标段或价格策略。

无可验证字段时：

- 明确写“源数据未包含可验证的军种/业务单元字段”；
- 不得虚构万科物业、万物梁行等模板示例值；
- 可用最接近的项目/区域维度替代，但必须说明替代原因。

### 6.3 `3、SKU维度`

必须优先按历史含税/未税同一口径计算 Top SKU：

- 至少 Top 5，高支出 SKU 不足 5 个则全部；
- 表格尽可能包含：清单序号、商品名称、品牌、规格、单位、数量、历史均价、含税/未税总额、支出占比；
- 数据支持时计算 Top 5 / Top 10 集中度、80% 支出对应的 SKU 数量；
- 识别高金额 SKU、高数量低金额 SKU、长尾 SKU；
- 明确重点议价/公开价对标/锁价对象。

不得把不同品牌、规格、单位、税率的价格直接混比。

### 6.4 `4、免运额度`

该栏不能只填一个金额。必须先形成配送经济性分析：

1. 历史订单存在 `订单编号 + 订单金额` 时，至少划分 4 个订单金额区间；
2. 每档统计订单数和订单占比，可得时增加金额/金额占比；
3. 识别小额高频订单比例、项目分散度、区县/异地配送和紧急配送；
4. 纳入历史起订/免运规则和本轮供方对最低起送金额/起订量的实际反馈；
5. 分析免运/最低配送门槛对报价、订单合并和履约的影响。

AI 可给 `方案A/方案B/建议区间`，但正式阈值必须采购员确认。

### 6.5 Spend Gate

历史数据足够时，支出分析至少满足：

- “整体”包含不少于 4 个可追溯数字事实；
- 模板可用维度中至少 2 个形成数字表格；
- SKU 表至少 5 行（不足 5 个 SKU 时全部）；
- 存在订单级金额时，免运分析至少 4 个金额区间；
- 至少 3 条带数字证据的关键发现；
- 至少 3 条当前项目采购动作；
- 每条采购动作能回指某个金额、占比、订单结构、价格或履约证据。

数据不足时必须降级分析：当前需求量+参考价做计划支出结构；只有数量做数量集中度；完全无金额依据则列缺失、影响和补充建议。不得只写“暂无数据”。

## 7. 当地供应市场行情分析 — 严格对应模板两个子块

### 7.1 `市场情况`

至少形成以下逻辑，不得只写“市场成熟、竞争充分”：

1. **企业可触达供应市场**：官方库本品类供方数、明确区域覆盖数、实际邀约数、明确回复数、最终短名单数，以及账期/SKU覆盖/配送/保证金等条件接受情况；
2. **本地供应格局**：生产商、品牌代理、经销商、综合贸易商、区域配送商、电商等结构及标准化/透明度；
3. **价格与上游趋势**：近期核心原材料/成品价格方向及驱动，不能量化时给方向和证据；
4. **本地履约因素**：项目点位分散、配送半径、区县/跨市、订单频次、小额订单、仓储、车辆、人工、搬运、紧急配送；
5. **政策/标准**：只写与当前品类直接相关的监管、质量、安全、环保或标准要求；
6. **市场结论**：说明竞争充分度、主要价格风险和对本次招标的实际影响。

Web 可用时原则上至少 3 个独立公开来源，优先近 12 个月；公开企业不得加入邀标池。

### 7.2 `成本构成情况`

按当前品类实际相关性，从以下成本池选择并排序：

- 采购/原材料；
- 制造/加工；
- 包装；
- 仓储/库存；
- 物流运输；
- 人工/装卸/现场交付；
- 销售/运营/售后；
- 税费；
- 合理利润。

至少分析 4 个真正相关成本项，每项说明“为什么影响本项目报价”。

只有存在可信来源时才可以写具体百分比/区间；无可靠来源时只写定性强弱和影响逻辑。严禁沿用模板 `X%` 或凭经验编造比例。

### 7.3 Market Gate

有内部供方数据且 Web 可用时至少满足：

- 至少 3 条内部供应市场数字信号；
- 至少 3 个独立公开来源；
- 至少 4 个成本构成/成本驱动项；
- 至少 2 条价格趋势或市场风险判断；
- 至少 2 条本地履约因素；
- 至少 3 条直接采购动作，例如重点议价 SKU、锁价/调价、公开价校验、最低起送/订单合并、区域履约验证、备选供方。

Web 不可用时仍需完成内部市场信号、成本驱动、本地履约和资料缺口，并标记 `public_research_incomplete`；不得用模型常识冒充公开行情。

## 8. 供应商短名单及入围理由

先写资源漏斗：

`官方库品类供方 → 区域/基础条件可匹配 → 实际邀约 → 明确回复 → 采购员最终入围`

再逐家写可追溯理由：账期、SKU覆盖、配送范围、仓储/车辆/物流、合作历史、已确认资质、保证金接受、售前售后能力等。

不得使用“实力雄厚、信誉良好”等无证据套话，不得修改人工确认名单。

## 9. 交货期 / 质保期 / 保证金

只消费当前项目事实。保证金优先消费 `sourcing-invitation.bid_bond` 当前项目计算结果，不得继承模板历史金额。

## 10. 供应商选择方法 / 目标价格 / 定标规则

必须形成完整闭环：

- 招标计划节点；
- 评标方法及商务/技术权重；
- 报价比较口径；
- 目标价依据；
- 中标家数与备选家数；
- 并列处理；
- 现场议价机制；
- 未达到目标价/超预算处理；
- 有效报价不足处理；
- 备选启动条件；
- 合同周期、付款、税率和价格管理。

这些规则必须来自 Human Decision / Enterprise Rule。模板示例降本率不得自动继承。

## 11. 风险防范

优先使用：

`风险场景 → 触发条件/证据 → 影响 → 处置动作 → 是否需人工确认`

至少检查需求变更、应标不足、有效报价不足、围串标/IP异常、签章问题、系统与盖章报价不一致、最低价并列、报价超预算、价格波动、单一供方、区域履约、关键 SKU、质量/资质、备选失效和数据完整性。

涉及废标、转竞谈、审批层级的正式动作只允许来自当前有效规则/采购员确认。

## 12. DOCX Rendering & Expansion Rule

内容深度优先于“把内容挤在原单元格里”。

生成 DOCX 时：

1. 保留企业模板的章节顺序、标题、表格样式、审批区和核心版式；
2. 分析内容超过原单元格空间时，允许增加段落、扩展行高、复制同样式表格行或让表格自然跨页；
3. 不得为了保持原页数而删除数字表、缩成一句话、截断分析或把多项内容塞成不可读文本；
4. 新增表格行必须继承原表格字体、边框、底纹、对齐和列宽逻辑；
5. 供应商名称、数据行不得拼接进“当地供应市场行情分析”“供应商短名单及入围理由”等章节标题；
6. 最终检查跨页表格、标题孤行、内容截断、重复字段和模板占位符。

## 14. Output

### A. `{{项目名称}}-strategy-data.yaml`

包含全部字段、来源、evidence、confidence、missing items、human decisions、内容深度指标和一致性检查。

### B. `{{项目名称}}-采购方案报告.docx`

基于企业 V3 原模板生成，报批前人工审核。

## 15. Guardrails

AI MUST NOT：

- 从公网新增邀标候选供方；
- 复制历史案例项目数据；
- 继承模板 X/XX/X% 或示例值；
- 虚构成本比例、市场涨跌幅、预算、降本目标、定标规则；
- 把部分周期实际支出写成全年实际；
- 混用含税/未税；
- 把不同规格/品牌/单位 SKU 的价格直接比较；
- 用 AI 建议覆盖采购员确认短名单；
- 为了控制页数删减核心分析。

## 16. Success Criteria

1. DOCX 结构遵循企业最新 V3 模板；
2. 支出分析四个模板子块均被正确完成或明确按数据不足规则处理；
3. 当地供应市场行情的“市场情况 + 成本构成情况”均达到分析深度；
4. 核心章节均形成“事实/数据 → 分析判断 → 采购动作”；
5. 历史分析、短名单、保证金、商务条件和定标规则全部可追溯；
6. 内容不足时明确保持 draft，不输出伪完整报批稿；
7. 采购员主要做关键决策确认，而不是重新补写整份策略报告。
