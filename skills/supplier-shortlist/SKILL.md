# Supplier Shortlist

## 1. Purpose

读取已确认的官方库供方长名单，以及各供方对邀标邮件/《招标意向征集登记表》的实际回复，生成一张与企业现有模板一致的《供方短名单筛选及入围原因》Excel。

本 Skill 只负责：

> 汇总回复 → 填入短名单表 → 整理是否入围及原因 → 等待采购员最终确认。

不负责：

- 复杂评分；
- 报价排名；
- 成本模型；
- 自动定标；
- 从公网新增供方；
- 替采购员作最终短名单决策。

## 2. Required Inputs

至少需要：

1. `official-supplier-matching` 已确认的库内长名单；
2. 供方邮件回复和/或回传的《招标意向征集登记表》；
3. 当前项目已确认的关键邀标条件；
4. `templates/供方短名单模板.xlsx`。

可选补充：

- 官方供方库中的注册资本、供方库分类、合作历史、联系人、邮箱、电话；
- 采购员人工补充的合作业绩、仓储/运输/授权/资质等已核实信息。

## 3. Source Rules

### 官方库字段优先用于

- 库内长名单；
- 是否有合作历史；
- 注册资本；
- 供方库分类；
- 邮箱、电话等已有联系人信息。

### 供方回复优先用于

- 是否有合作意向；
- 是否可供应清单全部物资；
- 配送区域；
- 账期接受情况；
- 保证金；
- 货期；
- 仓储、车辆、团队；
- 品牌授权、代理情况；
- 合作案例；
- 其他不参与原因。

### 禁止

- AI 根据公司名称猜测业绩、仓储、授权、资质或配送能力；
- 将“未回复”写成“否”；
- 把缺失信息自行补全；
- 修改供方真实回复的含义。

缺失内容使用：

- `未反馈`
- `待澄清`
- 或在明确无合作意向且无需继续收集时使用 `/`。

## 4. Output Columns

必须按照现有企业模板输出以下结构，不自行新增复杂评分列：

| 列 | 字段 |
|---|---|
| A | 序号 |
| B | 库内长名单 |
| C | 头部企业合作业绩（2家及以上） |
| D | 工厂、代理商、资质证书、基地、设施设备、仓储空间、运输工具等（具体类别具体分析） |
| E | 公司性质（是否为个体户） |
| F | 是否有合作意向 |
| G | 是否有合作历史 |
| H | 注册资本（万） |
| I | 供方库分类 |
| J | 是否入围及未入围原因 |
| K | 邮箱 |
| L | 电话 |

## 5. Workflow

### Step 1 — Load Longlist

以 `official-supplier-matching` 人工确认后的供方长名单为底表。

不得新增不在官方长名单中的供方。

### Step 2 — Merge Official Registry Data

尽可能补入：

- 合作历史；
- 注册资本；
- 供方库分类；
- 邮箱；
- 电话。

如官方库不存在对应字段则保留空白/待补充，不推断。

### Step 3 — Parse Supplier Replies

逐家读取供方回复，提取与当前品类相关的信息：

- 头部企业合作案例；
- 工厂/代理/品牌授权/资质；
- 仓储面积及库存能力；
- 配送车辆及配送团队；
- 是否能覆盖需求区域；
- 是否能供应全部清单；
- 是否接受当前账期；
- 是否接受保证金等关键邀标条件；
- 是否明确有合作意向；
- 明确不参与的原因。

只填写供方实际回复或已核实信息。

### Step 4 — Fill Necessary / Attention Conditions

按照模板归类：

#### 准入条件（必要条件）

- 头部企业合作业绩；
- 工厂/代理/资质/基地/仓储/运输等品类关键能力；
- 公司性质；
- 是否有合作意向。

#### 关注条件（非必要）

- 是否有合作历史；
- 注册资本。

关注条件用于采购员判断，但不得单独因为“无合作历史”或“注册资本较低”就自动判定不入围，除非当前企业规则明确把它设为必要门槛。

### Step 5 — Generate Column J

`是否入围及未入围原因` 只输出三种类型：

#### A. 建议入围

格式建议：

`是，{基于真实回复整理的主要满足条件}`

例如信息已明确时，可归纳：

- 接受当前账期；
- 可供应清单内全部物资；
- 配送范围满足；
- 有自有/明确配送资源；
- 能满足配送时效；
- 接受保证金；
- 其他当前项目关键条件。

不得写入供方未回复的优势。

#### B. 待澄清

当供方有合作意向，但关键必要信息缺失或回复互相冲突：

`待澄清：{具体缺失/冲突项}`

#### C. 不建议入围

当供方明确无合作意向，或明确不能满足当前项目关键条件：

直接写真实原因，例如：

- 无法满足配送范围；
- 不接受账期；
- 不缴纳投标保证金；
- 明确不参加；
- 其他供方明确反馈的原因。

不需要额外生成复杂评分说明。

### Step 6 — Human Checkpoint

生成表格后必须由采购员确认：

- 入围供方；
- 待澄清供方；
- 不入围供方及原因。

AI生成的是“短名单筛选表草稿”，不是最终定标结果。

## 6. Output

唯一主要交付物：

`{{项目名称}}供方短名单.xlsx`

要求：

- 使用 `templates/供方短名单模板.xlsx` 的原版式；
- 标题替换为当前项目名称；
- 保留库内长名单中所有参与本轮沟通的供方，包括未入围供方；
- 保留未入围原因，便于过程留痕；
- 不额外生成报告或长篇分析，除非用户明确要求。

## 7. Guardrails

- 官方库长名单是供应商身份 Source of Truth。
- 供方实际回复是参与意愿与条件 Source of Truth。
- 不新增公网供方。
- 不虚构业绩、资质、仓储、车辆、授权或合作意愿。
- 不把未回复自动判定为否。
- 不用非必要关注条件替代必要条件。
- 不自动定标。

## 8. Success Criteria

成功标准只有四条：

1. 官方长名单里的供方均被正确汇总；
2. 供方回复被准确映射到现有模板字段；
3. 每家供方的“入围/未入围原因”可追溯到真实回复或官方数据；
4. 最终输出是一张采购员可以直接审核的短名单 Excel。
